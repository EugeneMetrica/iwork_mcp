# Repository Guidelines

## Project Structure & Module Organization
- `src/` holds the TypeScript source. Entry points live in `src/index.ts` and `src/install.ts`.
- `src/tools/` contains the MCP tool registrations for each iWork app (`numbers.ts`, `pages.ts`, `keynote.ts`).
- `src/jxa.ts` contains `runJXA()` and `OsascriptError`.
- `dist/` is the compiled output (Node.js ESM) generated by `tsc`.
- `test/` contains tests using `node:test` + `tsx` with in-memory MCP transport.
- `test/helpers/` has `server.ts` (creates test McpServer + Client via InMemoryTransport) and `app-check.ts` (detects if iWork apps are installed).
- `screenshots/` stores README assets.
- Configuration lives in `tsconfig.json` and `package.json`.

## Build, Test, and Development Commands
- `npm install` installs dependencies.
- `npm run build` compiles TypeScript into `dist/` and marks `dist/index.js` executable.
- `npm run dev` runs `tsc --watch` for incremental builds during development.
- `npm test` runs fast unit tests (tool registration + OsascriptError parsing, ~300ms, no apps needed).
- `npm run test:integration` runs CRUD integration tests for Numbers, Pages, and Keynote (~6s, requires the iWork apps to be installed).
- `npm run test:all` runs both unit and integration tests.

## Coding Style & Naming Conventions
- TypeScript, Node.js ESM (`"type": "module"`) with `strict` compiler settings.
- Indentation: 2 spaces. Strings use double quotes in existing files.
- File naming is lowercase with `.ts` suffix; tool modules follow `numbers.ts`, `pages.ts`, `keynote.ts`.
- Keep CLI-facing output minimal; use `console.error` for server status logs.

## Testing Guidelines
- Tests use `node:test` (built-in) with `tsx` for TypeScript execution. No heavy test framework.
- Test files live in `test/` as `*.test.ts`. Helpers live in `test/helpers/`.
- Unit tests (`test/registration.test.ts`, `test/jxa.test.ts`) run without any iWork apps and verify tool registration and error parsing.
- Integration tests (`test/numbers.test.ts`, `test/pages.test.ts`, `test/keynote.test.ts`) perform CRUD operations against real iWork apps and skip automatically if the corresponding app is not installed.
- Tests use `InMemoryTransport.createLinkedPair()` from the MCP SDK to wire client and server in-process — no subprocess or stdio needed.
- When adding new tools, update `test/registration.test.ts` tool counts and add integration coverage if applicable.

## Commit & Pull Request Guidelines
- Commit history uses short, imperative summaries (e.g., “Fix Save As leaving document named \"Untitled\"”).
- Keep commits focused and describe user-visible behavior changes.
- PRs should include a clear description, steps to verify (commands or manual checks), and screenshots if UI/output changes affect `README.md` assets.

## Security & Configuration Tips
- This server executes JXA via `osascript`, so only run it on macOS with iWork installed.
- Local MCP clients should point to `dist/index.js` (see README) after building.
